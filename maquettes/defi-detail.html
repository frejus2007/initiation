Le blog qui ne devait pas mentir

← Retour au parcours

Mission

L'application web blog-lab.local utilise un système de publication d'articles. Le bouton d'accès au studio d'administration a simplement été masqué dans l'interface pour les utilisateurs non authentifiés, sans vérification de session côté serveur.

Votre objectif : Accédez à la page d'administration réservée aux éditeurs et récupérez le flag contenu dans le premier article en brouillon.

Environnement d'exercice

Exécutez cette commande dans votre terminal local pour démarrer le conteneur :

terminal 
$ ./lancer-lab.sh blog-lab
Cible active sur http://127.0.0.1:8080
ACCOMPAGNEMENT · NIVEAU DÉBUTANT

Démarche guidée

3 ÉTAPES RÉVÉLÉES

Au début du parcours, toute la méthode est visible. Les défis suivants s’appuieront sur ces notions et dévoileront progressivement moins d’indices.

  1. 01
    Observer les requêtes

    Dans le lab local, ouvrez les outils réseau du navigateur et repérez les requêtes liées au studio d’administration.

  2. 02
    Vérifier le contrôle d’accès

    Comparez le comportement de la page avec et sans session. Une interface qui masque un lien ne remplace pas une vérification côté serveur.

  3. 03
    Lire la ressource autorisée du lab

    Suivez la route identifiée dans cet environnement d’exercice, ouvrez l’article en brouillon et relevez son flag.

Valider le flag

Format attendu : PGH{...} · 5 tentatives restantes.

Indices progressifs

Indice 1 — Inspecter le code source client
Ouvrez les outils de développement (F12) et examinez les scripts JavaScript et liens commentés dans le code HTML de la page d'accueil.
Indice 2 — Contrôle d'accès côté serveur
Une ressource masquée visuellement peut rester directement accessible via son URL si le serveur ne contrôle pas la session.

Solution détaillée Verrouillée

L'explication méthodologique et les bonnes pratiques de remédiation seront accessibles dès la validation de votre flag.
